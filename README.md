## I build useful systems out of messy problems.

I work where **product thinking, automation, AI and the web** overlap. I like turning complicated workflows into tools that feel obvious to use — with strong architecture underneath, but without making the user care about the architecture.

My default bias is toward **practical products, local-first control, observable systems, reproducible tests and automation that stays reviewable**.

### NiakVIO

A community engine for Nuvio providers: aggregation, compatibility evidence, repair, native-device Labs and structured maintenance. The interesting part is not collecting providers — it is keeping a moving ecosystem **testable, repairable and publishable**.

`provider architecture` · `automation` · `native labs` · `validation` · `JavaScript`

### NiakGPT

A local-first power workspace for ChatGPT focused on Projects, long-thread performance, continuity, navigation and heavy project-based use. The goal is to add power **without turning ChatGPT into a second, noisier application**.

`browser extension` · `local-first` · `UX` · `automation` · `JavaScript`

## Principles I keep coming back to

```text
01  Make the complex thing understandable.
02  Automate repetition — not responsibility.
03  Prefer evidence over "it should work".
04  Keep failure states visible instead of manufacturing green checks.
05  Local-first when it genuinely gives the user more control.
06  Architecture exists to protect iteration, not to impress people.
07  Ship, observe, repair, simplify, repeat.
```
